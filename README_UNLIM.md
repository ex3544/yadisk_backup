# 🚀 Руководство: unlim_backup.py (Sergey Pukhir, ex3544)

Автономный кроссплатформенный загрузчик оригиналов фото и видео из «Безлимита» Яндекс.Диска для Windows, Linux и macOS.

---

## 🌟 Ключевые возможности

1. **Автоматическая инициализация базы данных:**
   - Если файла `unlim_state.db` нет рядом со скриптом — скрипт сам обращается к облачному API Яндекс.Диска, сканирует всю фото-ленту (photoslice) и создаёт локальную базу SQLite со всеми файлами в статусе `pending`.
2. **Прямое скачивание оригиналов (Direct CDN):**
   - Запрашивает прямые ссылки через `mpfs/url` (режим `attachment`).
   - Скачивает оригинальные несжатые файлы напрямую с серверов Яндекса на максимальной скорости вашего интернет-канала (в обход прокси).
3. **Выбор типа контента:**
   - Фотографии: `--media photos`
   - Видео: `--media videos`
   - Все медиа: `--media all`
4. **Гибкое управление очередями:**
   - Скачивание новых файлов: `--target pending`
   - **Повторный проход по сбойным нодам:** `--target skipped` (второй шанс для файлов, упавших ранее из-за ошибок серверов Яндекса)
   - **Всё за один запуск:** `--target all` — сначала очередь `pending`, затем один проход по `skipped`
   - Быстрый сброс ошибок: `--reset-skipped`
5. **Выбор направления:**
   - С конца очереди (старые архивы): `--from-end`
   - С начала очереди (свежие файлы): по умолчанию
6. **Политика «Без повторов» (Zero-retry skip):**
   - Если нода Яндекса зависла или вернула HTTP 500, файл помечается как `skipped` с записью точной причины в базу данных. Это исключает зависание пула потоков.
7. **Защита от «сочащихся» шардов:**
   - Иногда мёртвая нода отдаёт байты очень медленно, не вызывая read-таймаут. На каждый файл отводится общий дедлайн `max(120, timeout * 60)` секунд (~420 с при `--timeout 7`), после чего файл помечается `skipped` и поток освобождается.
8. **Автосортировка после скачивания:**
   - Флаг `--sort-after` сразу раскладывает скачанное по датам через `organize.py` (быстрый режим, без пересчёта MD5).

## 🖥️ Два режима работы

### Вариант 1: Интерактивный Веб-Дашборд (Рекомендуется)
Дашборд урезан до удобных **2 страниц** (Главная и Настройки) и позволяет управлять всеми процессами мышью.
При запуске **без параметров** скрипт автоматически открывает веб-панель:
```bash
python unlim_backup.py
# либо явно:
python unlim_backup.py --web
# либо напрямую:
python webui.py
```
Панель автоматически откроется в браузере по адресу: **`http://127.0.0.1:8000`**

- **Главная страница:**
  - Выбор цели: **🟣 Безлимит** или **🔵 Обычный Диск**.
  - Фильтр контента: только фото, только видео или все медиа.
  - Очередь: `pending` (новые файлы) или `skipped` (повтор ошибок).
  - Порядок: с конца (старые архивы) или с начала (свежие).
  - Тонкая настройка: количество потоков (1–24), размер батча (напр. 1000), число повторов (0 = до победного) и таймаут нод (напр. 7 сек).
  - Кнопки **«Запустить скачивание»** и **«Остановить»**.
  - Индикатор скорости в реальном времени (МБ/с и Мбит/с) и live-консоль процесса.
- **Страница Настройки:**
  - Ручной ввод и проверка **OAuth-токена** Яндекс.Диска.
  - Ручной ввод и валидация **Cookies** из Cookie-Editor.
  - Раздельное указание папок для сохранения: отдельно для **Безлимита**, отдельно для **Обычного Диска**.

## 📦 Перенос скрипта на другой ПК (Windows / Linux)

### Что скопировать на новый компьютер:
1. `unlim_backup.py` — автономный скрипт.
2. `cookies.json` — экспорт куки с `disk.yandex.ru` (через расширение Cookie-Editor).
3. `unlim_state.db` — (опционально) текущая база данных. Если базы нет, скрипт автоматически скачает список всех файлов из облака и создаст новую базу со статусом `pending`.

### Установка зависимостей:
Требуется только стандартный Python 3.10+ и библиотека `requests`:
```bash
pip install requests
```

## 🗄️ Базы данных: Безлимит vs Обычный Диск

- **Для Безлимита:** используется `unlim_state.db` (таблица `unlim_files`). Если файла нет, `unlim_backup.py` сам опросит скрытый API photoslice Яндекса и сгенерирует базу со статусом `pending`.
- **Для Обычного Диска:** используется `state.db` (таблица `files`). Это **отдельная база данных**, так как обычный Диск работает по официальному OAuth REST API с иерархией каталогов. Если её нет, скрипт `main.py` при запуске сканирует Диск и создаёт `state.db` со всеми файлами в статусе `pending`.

## 🛠️ Примеры команд запуска

### 1. Скачать все фотографии (с конца очереди, 10 потоков, таймаут 7 сек):
```bash
python unlim_backup.py --media photos --from-end --workers 10 --timeout 7 --out-dir "D:/Backup/Unlim"
```

### 2. Скачать все видеофайлы (начиная со свежих):
```bash
python unlim_backup.py --media videos --workers 6 --timeout 15 --out-dir "D:/Backup/Unlim"
```

### 3. Повторить скачивание ранее пропущенных файлов (`skipped`):
Если нужно проверить, не ожили ли ноды Яндекса для пропущенных фото:
```bash
python unlim_backup.py --target skipped --media photos --workers 10 --timeout 7 --out-dir "D:/Backup/Unlim"
```

### 4. Сначала новые, затем один проход по сбойным:
```bash
python unlim_backup.py --target all --media all --out-dir "C:/Unlim" --workers 4
```

### 5. Сбросить все `skipped` обратно в `pending`:
```bash
python unlim_backup.py --reset-skipped --media photos
```

### 6. Скачать тестовую пачку из 100 файлов:
```bash
python unlim_backup.py --batch-size 100 --batches 1 --from-end --out-dir "D:/Backup/Unlim"
```

## 📋 Таблица параметров CLI

| Параметр | По умолчанию | Описание |
| :--- | :--- | :--- |
| `--out-dir` | `/media/vb/backup Ya1/Unlim` | Папка для сохранения файлов. **На Windows обязательно указывайте явно**, например `--out-dir "C:/Unlim"` |
| `--media` | `photos` | Тип контента: `photos`, `videos`, `all` |
| `--target` | `pending` | Очередь: `pending` (новые), `skipped` (повтор сбойных) или `all` (сначала pending, затем один проход skipped) |
| `--from-end` | `False` | Скачивать с конца списка файлов (`rowid DESC`) |
| `--workers` | `10` | Количество параллельных потоков загрузки |
| `--timeout` | `7.0` | Таймаут соединения и чтения в секундах |
| `--batch-size` | `1000` | Размер одной порции файлов |
| `--batches` | `0` | Количество батчей (`0` = скачивать всё до конца) |
| `--cookies` | `cookies.json` | Путь к файлу куки |
| `--db` | `unlim_state.db` | Путь к файлу базы данных SQLite |
| `--reset-skipped`| — | Сбросить статус пропущенных файлов в `pending` |
| `--use-proxy` / `--proxy-url` | `False` / `http://127.0.0.1:10808` | Скачивать через локальный прокси |
| `--scan-only` | — | Собрать/обновить список файлов из облака в базу без скачивания |
| `--force` | — | Принудительно пересоздать базу данных с нуля (даже если файл уже есть) |
| `--sort-after` | — | После скачивания сразу разложить файлы по датам (`organize.py`, быстрый режим) |
| `--web` | — | Принудительно запустить веб-панель (http://127.0.0.1:8000) |
| `--cli` | — | Принудительный запуск в консоли без открытия веб-интерфейса |
