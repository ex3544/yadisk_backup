# Yandex.Disk Backup — массовое скачивание всего диска и безлимитного фото-хранилища

> **Готовый инструмент для миграции с Яндекс.Диска.** Скачивает обычные файлы через официальный REST API и скрытый безлимит (Photoslice — фото с телефонов) через куки браузера. Дедупликация по MD5, сортировка по полочкам, веб-интерфейс. Готовый установщик и portable — Python не нужен; из исходников зависимости ставятся сами.

## Что умеет

| Возможность | Как работает |
|---|---|
| 💾 **Скачивание обычного диска** | Через официальный REST API Яндекс.Диска в естественном порядке (`rowid ASC`). Нужен OAuth-токен. Авто-защита от сетевых зависаний (IPv4; MSS clamp — на Linux/macOS) |
| 📸 **Скачивание безлимита** | Скрытое мобильное фото-хранилище (Photoslice) напрямую с CDN серверов Яндекса на полной скорости канала (`unlim_backup.py`) |
| 🗂 **Сортировка по полочкам** | Раскладывает файлы по типам: Фото/Видео/Документы/Архивы/… с подпапками по годам и месяцам (`organizer.py`) |
| 📁 **Выбор папок через Проводник** | Нажатие кнопки «Обзор» открывает системное окно выбора папки ОС (Windows Explorer / Zenity / KDialog / Tkinter) |
| 🧹 **Дедупликация** | В базе — по MD5, при сортировке — по SHA-256; одну и ту же фотку в разных папках оставляет один раз |
| 🔄 **Resume** | Прерванное скачивание возобновляется с того же места. Хранит состояние в SQLite (`state.db` и `unlim_state.db`) |
| 🗄 **Резервные копии баз** | Снимки баз со статусами отдельно для Диска, отдельно для Безлимита или оба в одном ZIP. Восстанавливаются из «Диагностики», файлы на дисках не затрагиваются |
| 🌐 **Веб-интерфейс** | Тёмная тема в стиле Apple на `http://localhost:8000`, live-баннеры статуса баз, счётчики файлов и живой лог |
| ⚡ **Параллельность** | Число потоков подбирается автоматически по объёму ОЗУ (`auto_workers()`: 1 при ≤4 ГБ, 3 при ≤6 ГБ, 4 при большем). Можно задать вручную: для обычного диска 4–5 (больше → 429), для безлимита до 24 |
| 🛡 **Безопасность** | CSRF-защита, валидация путей, маскировка токена, atomic-write для куки |
| 🚀 **One-click запуск (из исходников)** | Запуск любого скрипта без параметров (`webui.bat`, `./webui.sh`, `python main.py`, `python unlim_backup.py`) сразу поднимает дашборд |

## Установка

### Вариант A — готовый установщик (рекомендуется)

1. Открой [Releases](https://github.com/ex3544/yadisk_backup/releases/latest) и скачай `YandexDiskBackup-<версия>-setup.exe`.
2. Запусти установщик. Права администратора не нужны: программа ставится в
   `%LOCALAPPDATA%\Programs\YandexDiskBackup`, ярлыки и автозапуск создаются
   только для текущего пользователя, окно UAC не появляется.
3. Готово. **Python устанавливать не нужно** — он уже внутри сборки.

Установщик сам проверит WebView2 Runtime и при необходимости поставит его (нужен интернет). Если WebView2 поставить не удалось, приложение всё равно запустится и откроется в браузере.

### Вариант B — portable ZIP (без установки)

1. Скачай `YandexDiskBackup-<версия>-portable.zip` из [Releases](https://github.com/ex3544/yadisk_backup/releases/latest).
2. Распакуй архив в любую папку.
3. Запусти `YandexDiskBackup.exe`. **Python не нужен.**

### Вариант C — из исходников (для разработки)

Нужен Python 3.11+.

- **Если Python уже установлен:** двойной клик по `webui.bat` — он проверит версию, поставит зависимости и запустит дашборд.
- **Если Python нет:** запусти `setup.bat` — он попробует поставить Python 3.13 через `winget`, затем зависимости и запустит приложение. Если `winget` недоступен, `setup.bat` откроет python.org: установи Python вручную с галочкой «Add Python to PATH» и запусти `setup.bat` снова.
- **Вручную:**
  ```bash
  git clone https://github.com/ex3544/yadisk_backup.git
  cd yadisk_backup
  python -m pip install -r requirements.txt
  python webui.py
  ```

`webui.bat` **не устанавливает Python** — он только проверяет его наличие. Автоматическая установка Python — в `setup.bat`.

### Где хранятся данные

Программа и изменяемые данные разделены (см. `paths.py`):

- при запуске из исходников, если рядом уже есть `.env`/`state.db`/`cookies.json`, всё остаётся в папке проекта — текущая установка продолжает работать как раньше;
- в собранной версии данные лежат в `%LOCALAPPDATA%\YandexDiskBackup` (базы, `.env`, куки, логи, отчёты);
- перенести состояние в другое место можно переменной `YADISK_DATA_DIR`.

Перед обновлением схемы БД автоматически создаётся резервная копия `*.db.bak_v<версия>_<дата>`.

### Первый запуск и диагностика

На чистой установке при первом открытии появляется окно настройки: OAuth-токен,
папка для обычного Диска, папка для Безлимита и необязательный ключ отправки
отчётов. Кнопка «Позже» закрывает окно — всё это можно указать на вкладке
«Настройки». Куки для Безлимита не обязательны на первом шаге.

**Резервные копии баз.** На вкладке **«Диагностика»** есть блок
**«Резервные копии баз»**. Копия хранит
только базу со статусами, ошибками и путями — сами файлы не копируются, поэтому
диски могут быть отключены. Доступны три равноправные кнопки: «Копия Диска»,
«Копия Безлимита» и «Общая копия (оба)» — последняя складывает обе базы и
описание в один ZIP. Перед созданием программа спрашивает подтверждение, а на
время создания блокирует кнопки.

Список показывает дату, версию программы, размер и число скачанных,
пропущенных и ожидающих файлов. Любую копию можно восстановить: программа
попросит ввести слово `ВОССТАНОВИТЬ`, сначала сама сохранит текущее состояние
(так что откат обратим), затем заменит базу. Файлы на дисках восстановление не
трогает. Всё, что скачано после даты копии, снова станет «в очереди»; файлы на
прежних местах отметятся скачанными без сети, а разложенные сортировкой —
скачаются заново.

Внизу вкладки **«Диагностика»** есть блок **«Пересоздание базы Безлимита»** —
крайняя мера, если база повреждена и «Обновить список файлов» не помогает.
Перед пересозданием автоматически сохраняется копия `unlim_state.bak-*.db`, а
кнопка включается только после ввода слова `ПЕРЕСОЗДАТЬ`. Все статусы
скачанного при этом сбрасываются, а если сортировка уже применялась, файлы
будут скачаны заново — подробности написаны прямо в окне.

На вкладке **«Диагностика»** есть две кнопки:

- **«Собрать отчёт»** — сохраняет ZIP в `reports/` внутри папки данных и
  показывает краткую сводку прямо в интерфейсе;
- **«Отправить отчёт»** — отправляет этот ZIP через Cloudflare Worker в Telegram.

В отчёт входят версия программы, сведения о системе и памяти, пути, настройки
без секретов, размеры и статусы баз, статусы задач, последние строки логов и
найденные ошибки. **Токен, куки, содержимое файлов и полные базы в отчёт не
попадают** — все строки дополнительно проходят редактирование секретов.

**Ключ отправки отчётов** — это не ключ Яндекса. Это общий секрет Cloudflare
Worker, который пересылает отчёты в Telegram. Публичная сборка ключа не
содержит. Ключ выдаёт **ex3544**; без него отчёт всё равно собирается и
остаётся на диске, но кнопка «Отправить отчёт» ничего никуда не отправит.
Ключ хранится локально в `DATA_DIR\.report_key.txt` и в отчёт не включается.
Не публикуй ключ: любой, кто его получит, сможет отправлять отчёты в бота.

### Оконный режим и трей

В установленной версии приложение запускается ярлыком **Yandex.Disk Backup** или
файлом `YandexDiskBackup.exe` — открывается отдельное окно с дашбордом (Edge
WebView2), без вкладки браузера. В portable-версии — тем же `YandexDiskBackup.exe`
из распакованной папки.

При запуске из исходников то же самое доступно через:

```bash
python launcher.py
```

- в системном трее появляется значок: «Открыть окно», «Открыть в браузере»,
  «Папка данных», «Выход»;
- закрытие окна **сворачивает приложение в трей**, задачи продолжают работать;
- полный выход — только через пункт «Выход» в трее.

Сервер слушает `127.0.0.1` (наружу не открыт). Если порт 8000 занят, берётся
следующий свободный; если приложение уже запущено, второе окно не создаётся —
открывается браузер с уже работающим экземпляром. Переопределить адрес/порт
можно переменными `WEBUI_HOST` и `WEBUI_PORT`. Если WebView2 недоступен,
приложение открывается в браузере, а трей остаётся рабочим.

Для оконного режима из исходников нужны `pywebview`, `pystray` и `Pillow`
(они уже в `requirements.txt`).

## Использование

### Настройки

1. Открой вкладку **«Настройки»**.
2. **OAuth-токен:** получи на [yandex.ru/dev/disk/poligon](https://yandex.ru/dev/disk/poligon/), вставь, нажми **«Проверить»**, затем **«Сохранить»**.
3. **Папка для обычного Диска** и **папка для Безлимита** — например `D:\YandexDiskBackup\Disk` и `D:\YandexDiskBackup\Unlim`. **Не указывай корень диска.**
4. **Cookies** — нужны только для Безлимита (см. ниже).

### Главная

- **«Быстрый запуск: скачать всё»** — полный цикл для обычного Диска и Безлимита одновременно, настройки пошагового режима не используются. Сначала программа проверяет облако на новые файлы, затем скачивает новые и повторяет сбойные: ошибки Диска (`failed`) и пропущенные файлы Безлимита (`skipped`). Повтор идёт до **3 проходов** с паузой 60 секунд; если проход не принёс ни одного файла, проходы прекращаются досрочно. Число проходов меняется полем «Проходов по сбойным» (1–5). После завершения показывается итоговое окно с числами отдельно по Диску и Безлимиту, а число ошибок видно и в бейджах.
- **Автосортировка** («Разложить фото/видео по датам») может занять много времени. Её можно не включать и сделать позже на вкладке **«Организация»**, когда всё скачается.
- **«Пошаговый режим»** — выбери **«Безлимит»** или **«Обычный Диск»**, укажи тип медиа, очередь, порядок файлов, число потоков, размер батча и таймаут. Затем:
  1. **«Обновить список файлов»** — обойти облако и добавить в базу новые файлы выбранного раздела. Статусы уже скачанных сохраняются, ничего не скачивается. Полное пересоздание базы Безлимита с нуля есть только на вкладке «Диагностика» и требует особого подтверждения.
  2. **«Запустить скачивание»** — начать выгрузку по выбранным настройкам.
  3. **«Остановить»** — прервать выгрузку; прогресс и очередь сохраняются.
- **«Сторож свободного места»** — останавливает выгрузку, если свободного места меньше порога.
- **«Сброс очереди»** — возвращает ошибочные, пропущенные и зависшие файлы в очередь. Скачанные файлы не удаляются.

### Безлимит (фото с телефона)

Яндекс прячет фото с мобильных приложений в скрытом хранилище. Через REST API оно не отдаётся, но можно достать через куки браузера:

1. Установи расширение [Cookie-Editor](https://chromewebstore.google.com/detail/cookie-editor/hlkenndednhfkekhgcdicdfddnkalmdm).
2. Зайди на [disk.yandex.ru](https://disk.yandex.ru/client/disk) и залогинься.
3. Кликни иконку Cookie-Editor → **Export → Export as JSON**.
4. Вкладка **«Настройки»** → поле «Cookies» → вставь JSON → **«Проверить»** → **«Сохранить»**.
5. Вкладка **«Главная»** → выбери **«Безлимит»** → **«Обновить список файлов»** → **«Запустить скачивание»**.

### Организация скачанного

1. Вкладка **«Организация»** → укажи папку с файлами.
2. Выбери схему раскладки.
3. **«Отчёт»** — покажет, куда что ляжет и сколько найдётся дубликатов, ничего не перемещая.
4. **«Применить сортировку»** — реально разложит файлы. Дубликаты уедут в `_duplicates/`.

Если включить **«Сортировать сразу»**, кнопка «Отчёт» разложит файлы без предпросмотра и без поиска дубликатов (MD5).

Структура при схеме «По типам → год → месяц»:

```
Папка/
├── Фото/2024/2024-08/...
├── Видео/2023/2023-07/...
├── Документы/
├── Архивы/
├── Программы/
├── Аудио/
├── Прочее/
└── _duplicates/  ← дубликаты сюда (можешь потом удалить)
```

## CLI (если UI не нужен)

```bash
# Обычный диск
python main.py check                    # проверить токен
python main.py scan                     # построить карту диска
python main.py download --workers 4     # скачать всё
python main.py retry-failed             # повторить упавшие
python main.py verify                   # проверить MD5
python main.py stats                    # статистика

# Безлимит (нужен cookies.json)
python unlim_backup.py --scan-only                      # собрать список фото/видео
python unlim_backup.py --target pending --media all \
    --out-dir "D:/Unlim" --workers 4                    # скачать новые
python unlim_backup.py --target skipped --media all \
    --out-dir "D:/Unlim" --workers 4                    # повторный проход по сбойным
python unlim_backup.py --target all --media all \
    --out-dir "D:/Unlim" --workers 4                    # pending, затем один проход skipped
# без параметров — сразу открывает WebUI

# Сортировка
python organize.py --input "D:/Backup"                  # отчёт
python organize.py --input "D:/Backup" --action move    # применить
```

## Сборка установщика (Windows)

1. Поставьте зависимости сборки:

   ```bash
   python -m pip install -r requirements.txt "pyinstaller>=6.0"
   ```

2. Соберите приложение (onedir):

   ```bash
   python build_exe.py
   # результат: dist\YandexDiskBackup\YandexDiskBackup.exe
   ```

3. Установите [Inno Setup 6](https://jrsoftware.org/isinfo.php) и соберите установщик:

   ```bash
   python build_installer.py
   # результат: installer_output\YandexDiskBackup-35.5.3-setup.exe
   ```

Установщик ставит программу в `%LOCALAPPDATA%\Programs\YandexDiskBackup`
(только для текущего пользователя, без прав администратора), создаёт ярлыки и,
по желанию, автозапуск. Данные (базы, `.env`, куки, логи)
остаются в `%LOCALAPPDATA%\YandexDiskBackup` и **не удаляются при удалении
программы**.

Ключ отправки диагностических отчётов можно встроить в установщик: положите
его в локальный `.report_key.txt` или переменную `REPORT_KEY` перед сборкой.
Ключ не попадает в репозиторий и не выводится в консоль. Сборка без ключа:
`python build_installer.py --no-key` — тогда ключ вводится вручную на вкладке
«Диагностика».

Если WebView2 Runtime на компьютере нет, установщик сам запустит официальный
Microsoft Edge WebView2 Bootstrapper (нужен интернет). Если установить не
удалось, приложение всё равно запустится и откроется в браузере. Загрузчик
скачивается при сборке установщика с сайта Microsoft и проверяется по
цифровой подписи; в git он не попадает.

4. По желанию — переносимый ZIP без установки:

   ```bash
   python build_portable.py
   # результат: dist\YandexDiskBackup-35.5.3-portable.zip
   ```

   Архив распаковывается в папку `YandexDiskBackup` и запускается двойным
   кликом по `YandexDiskBackup.exe`. Рабочие данные и секреты в него не
   включаются; при первом запуске создаётся чистая папка данных.

## Обновления

- История изменений: [CHANGELOG.md](CHANGELOG.md).
- Готовые сборки лежат в разделе
  [Releases](https://github.com/ex3544/yadisk_backup/releases): установщик и
  portable ZIP. CI собирает их автоматически по тегу `v*`.
- В приложении: **«Диагностика» → «Обновления» → «Проверить обновления»**.
  Если вышла новая версия, появляется кнопка **«Обновить до X.Y.Z»**: установщик
  скачивается с GitHub с показом прогресса, сверяется по SHA-256, затем
  **«Перезапустить и установить»** закрывает программу, ставит обновление и
  снова её открывает. Настройки и данные в `%LOCALAPPDATA%` сохраняются.
  Права администратора не нужны — установка идёт в папку пользователя.
  Для portable-сборки ZIP распаковывается поверх папки. Одно ограничение
  остаётся: сборка не подписана сертификатом, поэтому при первом запуске
  скачанного установщика SmartScreen может спросить «Всё равно запустить?».
- Публичные сборки **не содержат ключ отправки отчётов**. Ключ выдаёт
  **ex3544**; он вводится на вкладке «Диагностика» → «Ключ отправки» и хранится
  только на компьютере. Без ключа отчёт остаётся на диске.
- Чтобы выпустить обновление: поднимите `APP_VERSION` в `version.py`,
  закоммитьте, поставьте тег `v<версия>` и запушьте его. GitHub Actions соберёт
  установщик и опубликует Release. При обновлении базы, настройки и куки в
  `%LOCALAPPDATA%\YandexDiskBackup` сохраняются.

## Часто задаваемые вопросы

### Запустил `webui.bat`, а он говорит «Python is not installed»

Запусти `setup.bat` — он попробует поставить Python 3.13 через `winget`. Если `winget` недоступен, установи Python с [python.org/downloads](https://www.python.org/downloads/) и **обязательно** отметь галочку «Add Python to PATH». После этого закрой все cmd-окна и запусти `webui.bat` снова.

### Установка зависимостей зависла

Проверь интернет. Если медленный — `pip install -r requirements.txt` может занять до 5 минут.

### При запуске пишет «Failed to install dependencies»

Скорее всего pip не имеет доступа в интернет (фаервол / прокси). Попробуй вручную:
```bash
pip install -r requirements.txt
```
Если ошибка повторится — скриншот в issue на GitHub.

### Сервер запустился но браузер не открылся

Открой вручную: http://localhost:8000

### Скачивание прерывается

- **БД сохраняет прогресс** на каждом файле — просто запусти скачивание снова, оно продолжит
- Если совсем застряло — на вкладке **«Главная»** открой блок **«Сброс очереди»** и верни ошибочные, пропущенные или зависшие файлы в очередь. Скачанные файлы не удаляются.

### Токен перестал работать

OAuth-токен Яндекса живёт примерно год. Получи новый на [yandex.ru/dev/disk/poligon](https://yandex.ru/dev/disk/poligon/) и сохрани через UI (кнопка «Удалить» рядом со старым → вставь новый).

### Cookies перестали работать (для безлимита)

Сессионные куки браузера живут несколько часов / дней. Зайди в браузере на disk.yandex.ru заново, экспортируй cookies снова через Cookie-Editor и обнови в UI.

### Файлы падают с `HTTP 500`, `Read timed out`, `IncompleteRead`

Это не баг программы, а **сгоревшие/недоступные серверы хранения Яндекса**. Такие файлы помечаются `failed` (диск) или `skipped` (безлимит) с причиной. Когда Яндекс починит серверы, их можно добрать:

```bash
python main.py retry-failed                        # диск: failed → pending → скачивание
python unlim_backup.py --target skipped --media all --out-dir "ПУТЬ" --workers 4
```

Не запускай массовый сброс ошибок, если Яндекс ещё не восстановил шарды — мёртвые файлы вернутся в очередь и замедлят выгрузку.

### Потоки безлимита «висят» на одном файле

Мёртвый шард может отдавать байты очень медленно, не вызывая таймаут. В `unlim_backup.py` есть предохранитель: на каждый файл отводится `max(120, --timeout * 60)` секунд (по умолчанию ~420 с), после чего файл помечается `skipped`, а поток освобождается.

### Яндекс блокирует на 429 (Too Many Requests)

- Снизь `MAX_WORKERS` до 2-3
- Подожди 10-15 минут и попробуй снова
- Программа сама делает паузы при 429

### Указал DOWNLOAD_DIR=C:\ и сервер виснет

Программа защищена от этого — не обходит корни дисков. Укажи конкретную подпапку, например `C:/YandexBackup`.

### Безопасно ли использовать?

- ✅ **Токен и куки** хранятся только локально на твоём диске (`.env` и `cookies.json`)
- ✅ Эти файлы в `.gitignore` — не попадут в git
- ✅ Web-UI слушает только `127.0.0.1` — недоступен из интернета
- ✅ CSRF-защита: чужой сайт не сможет дёрнуть API
- ✅ Path traversal: нельзя сортировать системные папки (`C:/Windows` и т.д.)
- ⚠️ Безлимит через куки — серая зона по ToS Яндекса. Используй **только для своих данных** перед отменой подписки

### Что делать, если база испортилась или я пересоздал её по ошибке?

Открой вкладку **«Диагностика» → «Резервные копии баз»** и восстанови нужную
копию. Программа сначала сохранит текущее состояние, поэтому восстановление
обратимо. Если подходящей копии нет, создай новую заранее — например, перед
экспериментами с базой. В копию попадают только статусы и пути; сами файлы на
дисках не копируются и не удаляются.

### Где взять ключ отправки отчётов?

Это общий секрет Cloudflare Worker, а не ключ Яндекса. Публичная сборка его не
содержит. Ключ выдаёт **ex3544**; без него отчёт собирается и остаётся на диске,
но никуда не отправляется. Не публикуй ключ: любой, кто его получит, сможет
отправлять отчёты в бота.

## Требования

### Готовая сборка

- Windows 10/11 (тестировалось на Windows 11)
